# Описание лабораторной работы

## Задача
Даны два отсортированных массива целых чисел длины M и N. Требуется вернуть `True`/ `False` есть ли общий элемент.

Цель: реализовать 4 разных алгоритма и выяснить, в каких случаях какой алгоритм эффективнее.

## Алгоритмы
* **Два указателя** (`algorithms/two_pointers.py`)
* **Бинарный поиск** (`algorithms/binary_search.py`)
* **Экспоненциальный поиск** (`algorithms/exponential_search.py`)
* **Двойной бинарный поиск** (`algorithms/double_binary_search.py`)

## Архитектура проекта
* `algorithms/` — реализация 4 алгоритмов
* `tests/test.py` — тесты для проверки корректности алгоритмов
* `test_time.py` — pytest-бенчмарки
* `plot.py` — построение графиков
* `main.py` — файл для запуска всего пайплайна
* `data/` — сырые данные замеров времени (`results.csv`)
* `plots/` — сгенерированные графики
* `Dockerfile` и `docker-compose.yml` — докер-инфра для удобства запуска

## Запуск проекта


### локально



# выводы по лабораторной работе

Как генерировались тесты:
Худший случай: В массив А записывались нечетные числа, в массив B — четные числа с равномерным распределением.

Замеры времени: Использовался системный таймер time.perf_counter().

Анализ тестов
1) Массивы одинакового размера (M = N, от 100 до 300 000) (plots/equal_sizes.png)

При M = N побеждает алгоритм «Два указателя»
Самым медленным оказался обычный бинпоиск, т.к. в худшем случае он делает N полных поисков по массиву длины N.

2) Сильно асимметричные массивы (M = 50, N растет до 1 000 000) (plots/fixed_m.png)

При росте N два указателя резко проигрывают, т.к. обязаны пошагово просмотреть весь миллион элементов.
Бинарный, экспоненциальный и двойной бинарный работают быстрее почти в 400 раз, т.к. сразу отсекают огромные куски массива B.

3) Зависимость от соотношения N / M (plots/varying_ratio.png)

График показывает точку перелома:
При N / M <= 5: быстрее работают «Два указателя».
При N / M >= 8..10: кривые пересекаются, и алгоритмы с бинарным делением начинают выигрывать.


# Выводы:

- При N / M <= 5 
Наиболее эффективны два указателя
Бинпоиск и экспоненциальный поиск проигрывают из-за большего количества операций.

- N / M >= 10
Наиболее эффективен экспоненциальный поиск. 
Он обеспечивает наилучшее время, т.к. производит сильно меньше операций.

- Двойной бинарный поиск: Имеет такую же скорость по времени, как и экспоненциальный, но в данной реализации требует доп память O(log M) из-за рекурсии
